🚀 libuv NEDİR? (En basit tanım)

libuv = Node.js’in asenkron çalışmasını sağlayan C kütüphanesidir.
Yani:

✔ Event Loop
✔ Thread pool
✔ Asenkron I/O
✔ Timer’lar
✔ Network
✔ File system işlemleri

gibi bütün arka plandaki ağır işleri yöneten altyapıdır.

Node.js JavaScript yazdığın yüzüdür,
libuv ise arkadaki motorudur.


🔥 Bir cümleyle:

👉 JavaScript tek thread, ama Node.js hızlı ve asenkron çalışıyorsa, bunun sebebi libuv’dir.


🧱 libuv ne işe yarar?

Node’un yaptığı pek çok olay JavaScript değil, libuv ile yapılır:

İşlem	            JS mi yapıyor?	            libuv mi?
Event Loop	            ❌                          	✔
Dosya okuma         	❌	                        ✔ (OS ile konuşur)
Ağ istekleri        	❌	                        ✔
setTimeout	            ❌                           ✔
Thread pool	            ❌                          	✔
TCP/UDP soket	        ❌                          	✔
DNS lookup	            ❌	                        ✔

JavaScript sadece callback'i yazdığın yerdir.
Derin işlerin hepsi libuv’de.

🔧 libuv nasıl çalışıyor?

libuv iki sistemi kullanır:


🌀 1) Event Loop

JavaScript’in yaptığı işler bittikten sonra libuv bir kuyruğa bakar:

Timer’lar

I/O tamamlanmış işler

setImmediate

close callbacks

Bu kuyruğu dönen yapıya event loop deriz.

Node.js'in ünlü "tek thread ama asenkron" yapısı tamamen buradan gelir.

🔧 2) Thread Pool

Bazı işler gerçekten CPU veya dosya beklemesi gerektirir:

Ağır dosya işlemleri

DNS lookup

Crypto hashing

Compression

Bu işleri libuv kendi oluşturduğu 4 thread'lik thread pool’a atar.
(İstersek 128’e çıkarabiliriz.)

Bu thread'ler işleri yapar → Bitince event loop'a “callback hazır” diye haber verir.

📦 Örnek: fs.readFile neden asenkron?

Çünkü:

JS kodu fs.readFile() der

libuv thread pool’a işi atar

Thread dosyayı okur

İş bitince event loop’a “hazır” der

Event loop callback’i çalıştırır

Sen sadece callback yazarsın ama arka planda libuv ile OS konuşur.

🛠 libuv Node içinde değil JavaScript dışında yazılmıştır

C ile yazılmıştır

Unix, Linux, macOS, Windows ile aynı API üzerinden konuşur

Node.js, Python, Rust, Julia gibi başka diller de kullanabilir (sadece Node’a özel değil)

Yani JavaScript sadece üstteki ince kabuktur.

🏎 Kısaca özet (çok net)

Node.js = JavaScript + libuv

JavaScript → kodu yazdığın yer

libuv → arkadaki tüm ağır işleri yapan motor

JavaScript tek thread → libuv çok thread
JavaScript yavaş → libuv OS seviyesinde hızlı işleri yapar
JavaScript I/O yapamaz → libuv yapar




🏊‍♂️ THREAD POOL NE DEMEK?
✔ Thread Pool = Bir grup hazır işçi

Bunlar bekliyor

İş gelince hemen işe dalıyorlar

İş bitince geri gelip sıraya giriyorlar

Yeniden işe hazır oluyorlar

🔥 Tanım:

Thread pool, belirli sayıda thread’in (işçinin) sürekli hazır beklediği ve gelen işleri çalıştırdığı bir havuzdur.

🏭 BENZETME (Ful net, nokta atışı)
🧱 Core = Sobanın kendisi
👷‍♂️ Thread = Sobaya odun atan işçi
👷‍♂️👷‍♂️👷‍♂️ Thread Pool = Sobanın yanında bekleyen 4 kişilik hazır işçi ekibi

Bu ekip:

Sürekli “iş var mı?” diye bekler

İş gelince hemen bir işçi gidip yapar

Bitince havuza geri döner

Yeni iş gelince başka işçi gider

Her iş için yeni işçi oluşturulmaz


🟢 Neden thread pool kullanılıyor?

Çünkü:

❌ Her iş geldiğinde yeni işçi (thread) oluşturmak pahalı
✔ 4–8 tane hazır işçi tutmak çok daha hızlı

Kısaca:

Thread oluşturmak pahalıdır.
Thread pool hızlıdır.


🟧 NODE.JS’TE THREAD POOL

Node.js’in içinde libuv vardır.
libuv’nin içinde de 4 thread’lik bir thread pool vardır.

Bu 4 işçi:

Dosya okuma/yazma

Şifreleme

Sıkıştırma

DNS

Ağır CPU işleri

gibi işleri yapar.

Bu yüzden Node.js tek thread görünse de:

✔ Arkada 4 gizli işçisi vardır = Thread Pool
🟦 AKLINDA KALACAK TEK CÜMLE
🧵 Thread = 1 işçi
🧵🧵🧵🧵 Thread pool = Hazır bekleyen işçi ekibi
🔥 Core = Sobanın kendisi
🏭 CPU = Bütün ev


Küçük bir örnek:

fs.readFile("abc.txt", () => {
  console.log("bitti");
});


Burada:

JS thread → işi libuv'ye yollar

libuv → thread pool’daki 4 işçiden birine verir

İşçi dosyayı okur

Bitince event loop’a "bitti" der

JS thread callback’i çalıştırır
