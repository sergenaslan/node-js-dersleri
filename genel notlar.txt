🔥 Node.js Nasıl Çalışır? (Genel Akış)

Aşağıdaki sıralama tüm Node.js’in çalışma mantığıdır:

Call Stack

Event Loop

Callback Queue / Microtask Queue

Thread Pool (libuv)

OS async I/O

Tek thread olan JS motoru

Şimdi bunu parça parça, fabrika benzetmesiyle anlatıyorum.



🧱 1) CALL STACK

Call Stack = İşçinin (JS thread’in) elindeki yapılacaklar listesi.

JS kodunu burada sırayla yürütür

Stack’te fonksiyonlar üst üste dizilir

Bir işçi sadece bu stack'i işler

🧵 JS = tek işçi = tek Call Stack

🔁 2) EVENT LOOP

Event loop = Sürekli etrafta dolaşan yönetici

Görevi:

“Call Stack boş mu?” diye bakar

Boşsa kuyruklardan iş alır

Doluysa bekler

Bitmiş işlerin callback’lerini sırayla içeri sokar

Event Loop → trafik polisi 🚦

📥 3) CALLBACK QUEUE

Callback Queue = İşçi için sırada bekleyen işler.

Timer’lar (setTimeout)

Ağ istekleri

Disk işlemleri (thread pool sonuçları)

Event emitter callback’leri

Hepsi buraya sıraya dizilir.

Event loop → call stack boşalınca buradan işçiye verir.

⚡ 4) MICROTASK QUEUE

Microtask Queue = VIP bekleme odası

Promise callback’leri

queueMicrotask

process.nextTick

Microtasks her zaman önce çalışır.

🧵🧵🧵🧵 5) THREAD POOL (libuv)

Thread Pool = 4 kişilik gizli işçi ekibi
Bu işçiler:

Dosya okuma

Sıkıştırma

Crypto

DNS

Ağır CPU işleri

gibi işlerde çalışır.

Önemli:

JS thread bu işleri kendisi yapmaz.
Sadece thread pool’a “şunu yap” der.

Bitince sonuç callback queue’ya düşer.

🖥 6) OS ASYNC I/O

Ağ isteklerinde (HTTP, TCP, UDP) Node.js çoğu zaman thread pool bile kullanmaz.

İşletim sistemi zaten asenkron ağ işlemi yapıyor.

Node sadece:

Ağ isteği başlatır

OS iş bitince Node’a sinyal verir

Event loop callback’i çalıştırır

🧱 NEDEN “ODUN – İŞÇİ – SOBA” BENZETMESİ BU KADAR TUTTU?

Çünkü Node.js’in mimarisi tam olarak şunlardan oluşuyor:

Thread → bir işçi

CPU Core → işçinin fiziksel çalıştığı makine

Call Stack → işçinin önüne banttan gelen işler

Thread Pool → arkada çalışan güçlü işçiler

Event Loop → etrafta gezen yönetici

Callback Queue → hazır işlerin bekleme alanı

OS async I/O → dışarıdan haber getiren sistem

Sen bunları eşleştirilebilir bir fiziksel modele dönüştürdün.

🌲 Odun → komut
👷 İşçi → thread
🔥 Soba → CPU core
🏭 Atölye → thread pool
👨‍💼 Yönetici → event loop
📦 Bekleme sırası → callback queue

Bu — beynin karmaşık sistemi anlaması için mükemmel bir temsil.

🔥 NASIL BU KADAR İSABETLİ GELDİ?

Çünkü node.js’te olan olaylar aslında fiziksel dünyaya çok benzer:

Her komut yakılması gereken bir odun gibi sırayla gelir

Tek işçi (JS thread) bunları sırayla işler

Bazı odunlar gerçekten çok büyük (file IO, crypto vs.)

İşi işçi değil atölye (thread pool) yapar

İş bitince “hazır odun” olarak geri döner

Yönetici bunu işçinin önüne koyar

İşçi yakar ve biter

Yani beynimiz bu modeli zaten doğal olarak böyle çalıştırıyor, bu yüzden benzetme çok oturuyor.
